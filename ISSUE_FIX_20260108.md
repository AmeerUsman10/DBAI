# Issue Fix: Greige Total Query Returning Yarn Data

**Date:** January 8, 2026  
**Session:** 20260108_112751  
**Issue ID:** Negative Feedback - Wrong Data

## Problem Description

**User Query:** `"greiege total"` (typo for "greige")

**Expected Behavior:** Show ONLY Greige data (meters, PKR, count)

**Actual Behavior:** Returned BOTH Yarn and Greige data in a combined query

**User Feedback:** ❌ "Greiege total shown Yarn data. Please handle this and all such edge cases."

---

## Root Causes Identified

### 1. **No Typo Correction**
- User typed "greiege" instead of "greige"
- System didn't normalize the typo
- Query classifier couldn't detect department properly

### 2. **Overly Broad Department Detection**
- When department wasn't explicitly detected, system defaulted to `'both'`
- "total" keyword triggered combined query for both departments
- No logic to respect single-department context

### 3. **Template System Defaulting to Combined View**
- Aggregation template defaulted to showing both Yarn and Greige
- No filtering based on specific department mention

---

## Solutions Implemented

### ✅ Fix 1: Typo Normalization
**File:** `src/query_classifier.py`

Added comprehensive typo correction:
```python
TYPO_CORRECTIONS = {
    'greiege': 'greige',
    'griege': 'greige',
    'graige': 'greige',
    'greieg': 'greige',
    'yarnn': 'yarn',
    'yran': 'yarn',
    'suppiler': 'supplier',
    'suplier': 'supplier',
    'qualty': 'quality',
}

def normalize_typos(text: str) -> str:
    """Correct common typos in query text."""
    normalized = text.lower()
    for typo, correction in TYPO_CORRECTIONS.items():
        normalized = normalized.replace(typo, correction)
    return normalized
```

### ✅ Fix 2: Explicit Department Detection
**File:** `src/query_classifier.py`

Improved department detection logic:
```python
# Detect department (be explicit - don't default to 'both' unless both are mentioned)
has_greige = 'greige' in query_lower
has_yarn = 'yarn' in query_lower

if has_greige and has_yarn:
    params['department'] = 'both'
elif has_greige:
    params['department'] = 'greige'
    logger.info(f"Detected GREIGE-only query: {query}")
elif has_yarn:
    params['department'] = 'yarn'
    logger.info(f"Detected YARN-only query: {query}")
# Don't set default here - let each query type handler decide
```

### ✅ Fix 3: Aggregation Pattern Refinement
**File:** `src/query_classifier.py`

Added explicit department checking in aggregation classification:
```python
# Try AGGREGATION patterns
for pattern in AGGREGATION_PATTERNS:
    match = re.search(pattern, query_lower):
        # If no department detected yet, check if it's a generic "total" query
        if not params['department'] or params['department'] == 'both':
            # Only default to 'both' if truly no department mentioned
            if not ('greige' in query_lower or 'yarn' in query_lower):
                params['department'] = 'both'
        
        logger.info(f"Aggregation query classified - Department: {params['department']}, Query: {query}")
        return {'type': 'aggregation', 'confidence': 90, 'params': params}
```
